# Практика 2. Сравнение экспериментов PandaPickCube

## Методика
Baseline: 4096 сред, 1001 итерация, seed обучения1. PPO learning_rate0.001, adaptive. Actor/critic MLP512–256–128, ELU. В каждом эксперименте менялся один параметр. SR:10 эпизодов, seed42–51, успех при конечном расстоянии куба до цели <0.05м. Baseline и промежуточная модель самостоятельного эксперимента оценены на CPU; max_iters_500 и qpos_strong — в Colab. Численные различия CPU/GPU и малая выборка ограничивают точность сравнения.

## Анализ по схеме курса

### Масштаб обучения
Изменили1001→500 итераций. Ожидали сократить время ценой возможного снижения качества. Получили1274.76 и7/10 против1359.47 и10/10. Время2388.9с против приблизительно4524.7с baseline. Обе метрики снизились. При одинаковой функции награды это согласуется с меньшим объёмом обучения; один запуск и10эпизодов не устанавливают статистическую закономерность.

### Основная компонента box_target
Вес8→40. Ожидали более сильный стимул переносить куб и рост суммарной награды. Через примерно10минут среда вернула NaN, PPO остановился. Первый запуск не завершён. Повтор с теми же параметрами под именем box_target_strong_recovery прошёл1001итерацию за4451.87с: reward862.83, SR0/10. Гипотеза об улучшении не подтвердилась. Усиление основной компоненты само по себе не гарантирует удачного обучения: возможны неоптимальная стратегия и вариативность PPO. Точная причина ухудшения не установлена. Пример ожидаемого результата из урока не подменяет измерение.

### Вспомогательная компонента robot_target_qpos
Вес0.3→30. Ожидали доминирования поощрения сохранения стартовой позы. Награда выросла до4535.98, SR упал до0/10. Рост reward не означает улучшения PickCube: PPO оптимизирует изменённую функцию награды. По независимой метрикеSR это самое сильное измеренное ухудшение, −100п.п. Поведение следует проверить по сохранённому видео logs/qpos_strong/evaluation.mp4, не подменяя наблюдение ожиданиями урока.

### Самостоятельная гипотеза, записанная до запуска
Изменили no_floor_collision0.25→2.5. Гипотеза: reward вырастет, SR снизится, поскольку усиление вспомогательной цели может отвлекать от доставки куба. Запуск остановился из-за NaN на469-й итерации. Сохранена модель450, безопасно загружена и оценена на10эпизодах:8успехов,10захватов. Награда на450-й итерации1500.08. Направления совпадают с гипотезой, но она не подтверждена изолированно: у baseline1001итерация, а у восстановленной модели451. Для причинного сравнения нужен одинаковый бюджет обучения и повторения.

## Основной вывод
Для качества решения задачи выбирается SR. Абсолютные значения награды при разных весах отражают разные целевые функции и не ранжируют качество политики. Изменение масштаба снизило обе метрики; усиление robot_target_qpos увеличило reward при полном провале задачи. NaN — отдельный сбой численной устойчивости, точная причина которого не установлена.
